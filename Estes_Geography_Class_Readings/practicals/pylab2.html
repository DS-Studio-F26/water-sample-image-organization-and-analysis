1 What Is Object-Oriented Programming in Python

1.1 What Are Objects?

An object is a model of a real-world entity. It encapsulates both data and behaviors into a single unit:

  • Data (properties): Attributes or characteristics of an object.
  • Behaviors (functions/methods): Actions or operations an object can perform.

Consider a Satellite image as an object, it has:

  • Properties: (attribute or state)
    • pixel value, pixel size, bands, Coordinate Reference System, cloud cover percent.
  • Behaviors or Methods: (do something (procedures, and functions))
    • reproject(crs="EPSG:4326"): Reprojection and changing the CRS.
    • resample(new_resolution=30):Resampling and Adjusting the spatial resolution or aligning grids.
    • calculate_ndvi(): NDVI calculation.
    • apply_filter(): Apply a spatial or spectral filter for noise reduction or feature enhancement.

OOP provides an intuitive framework for working with data, allowing for modular and reusable code that can handle the complexity of analyses.

1.2 Define a Class in Python

Primitive data structures, such as numbers, strings, and lists, are well-suited for representing basic pieces of information such as an item’s price, a file’s name, or a list of students in a class. But what happens when the data you need to represent becomes more complex?

Imagine you need to track information about several images. For each image, you might need to store:

  • The sensor type
  • Spectral resolution
  • Spatial resolution
  • Temporal resolution

You might initially represent each image as a list:

image1 = ["Optical", 4, 3.5, 5]
image2 = ["Optical", 13, 10, 5]
image3 = ["Radar", "1–180 (nm)", "SAR", 12]

Do you agree this is not an efficient way to store them?

This approach is neither readable nor easy to maintain:

  • Accessing elements like image1[0] or image2[2] makes the code less clear and harder to understand without context.
  • Misunderstanding indices can lead to bugs.

Additionally, there is no data consistency:

  • Not all images have the same type or format for attributes.
  • For example, image3 has its second and third properties in a different format or type compared to the others

A great way to make this type of code more manageable and more maintainable is to use classes. A class is a blueprint for creating user-defined objects. It defines the structure (attributes) and behavior (methods) that the objects will have. However, a class itself does not store any specific data; it only describes how objects created from it should look and behave.

1.3 Classes vs Instances

The SatelliteImage class defines the following:

Attributes:

  • sensor_type: The type of sensor (e.g., Optical or Radar).
  • spectral_resolution: The number of spectral bands.
  • spatial_resolution: The resolution in meters (e.g., the size of the ground area represented by each pixel).
  • temporal_resolution: The revisit time in days.

Methods:

  • The class can have additional methods to define behaviors, such as calculating statistics or displaying metadata.

An instance is a specific object created from a class. It holds unique, real-world data that conforms to the structure defined by the class.

How to Define a Class?

Class Basics - Classes in Python are defined using the class keyword, followed by the class name (in PascalCase) and a colon (:). - Example: python class SatelliteImage: pass pass is used as a placeholder when the class has no functionality yet.

Naming Conventions: Class names follow Capitalized Words (PascalCase) notation. Example: SatelliteImage

Adding Properties to a Class To define properties (attributes) for a class, use the special method .__init__(). This method initializes each instance of the class with specific attributes.

Class Attributes vs Instance Attributes

  • Instance Attributes:

Specific to each object. Defined in the .__init__() method using self. Every time a new image object is created, .__init__() sets the initial state of the object by assigning the values of the object’s properties. That is, .__init__() initializes each new instance of the class. You can give .__init__() any number of parameters, but the first parameter will always be a variable called self. When a new class instance is created, the instance is automatically passed to the self parameter in .__init__() so that new attributes can be defined on the object. self refers to the specific instance of the class. Attributes defined using self are instance attributes, meaning their values vary for each instance.

  • Class Attributes:

Shared across all instances of the class. Defined directly under the class name, outside of any methods.

Note: Class attributes are defined directly beneath the first line of the class name and are indented by four spaces. They must always be assigned an initial value. When an instance of the class is created, class attributes are automatically created and assigned to their initial values.

Use class attributes to define properties that should have the same value for every class instance. Use instance attributes for properties that vary from one instance to another.

2 Inheritance in Python

Inheritance is a fundamental concept in object-oriented programming, allowing one class (a child class) to inherit attributes and methods from another class (a parent class). This models a “is-a” relationship, where the child class is a specialized version of the parent class.

Understanding Inheritance

You can think of inheritance like genetic inheritance: - Attributes: Just as you may inherit your hair color from your parent, a child class inherits the attributes of the parent class. If you decide to color your hair purple, you override the inherited hair color attribute. - Methods: You also “inherit” behaviors, like speaking a language. If you learn a new language, you extend your capabilities by adding an attribute your parent class doesn’t have.

Key Concepts of Inheritance

  • Parent Class (Base or Super Class): The class being inherited from.
  • Child Class (Derived or Sub Class): The class that inherits attributes and methods from the parent class.
  • Overriding: Child classes can redefine attributes or methods from the parent class.
  • Extending: Child classes can add new attributes or methods that the parent class doesn’t have.

Example: SatelliteImage Class

Here’s an example where we extend the functionality of a SatelliteImage class to include specific types of satellite image types of satellite images.

2.1 Different levels of inheritancy

2.1.1 Single Inheritance

Single inheritance involves a child class inheriting from one parent class. This reduces code repetition and models relationships effectively.

# Parent Class
class SatelliteImage:
    def __init__(self, sensor_type, spectral_resolution,
                 spatial_resolution, temporal_resolution):
        self.sensor_type = sensor_type
        self.spectral_resolution = spectral_resolution
        self.spatial_resolution = spatial_resolution
        self.temporal_resolution = temporal_resolution

    def description(self):
        return (
            f"Sensor Type: {self.sensor_type}, "
            f"Spectral Resolution: {self.spectral_resolution}, "
            f"Spatial Resolution: {self.spatial_resolution} meters, "
            f"Temporal Resolution: {self.temporal_resolution} days"
        )

# Child Class (Extending Parent Class)
class OpticalImage(SatelliteImage):
    def __init__(self, sensor_type, spectral_resolution,
                 spatial_resolution, temporal_resolution,
                 cloud_coverage):
        # Inherit attributes from parent class
        super().__init__(sensor_type, spectral_resolution,
                         spatial_resolution, temporal_resolution)
        # Add new attribute
        self.cloud_coverage = cloud_coverage

    def description(self):
        # Override description method
        parent_desc = super().description()
        return f"{parent_desc}, Cloud Coverage: {self.cloud_coverage}%"
image1 = SatelliteImage("Radar", "1–180 nm", "SAR", 12)
print(image1.description())
Sensor Type: Radar, Spectral Resolution: 1–180 nm, Spatial Resolution: SAR meters, Temporal Resolution: 12 days
# Create an instance of the child class
image2 = OpticalImage("Optical", 13, 10, 5, 20)
print(image2.description())
Sensor Type: Optical, Spectral Resolution: 13, Spatial Resolution: 10 meters, Temporal Resolution: 5 days, Cloud Coverage: 20%

What is super()?

The super() function provides access to the methods and attributes of a parent class, allowing child classes to reuse functionality without explicitly referencing the parent class name.

2.1.1.1 Benefits of super()
  1. Reduces Duplicate Code:
    • Avoids re-implementing the same logic in the child class.
  2. Simplifies Maintenance:
    • Changes made in the parent class are automatically inherited by child classes without needing to update each explicit relationship (e.g., 5 days, Cloud Coverage: 20% in the previous example)

2.1.2 Multi-Level Inheritance

In multi-level inheritance, a child class inherits from a parent class, which itself inherits from another class. This forms a chain of inheritance where attributes and methods propagate through the hierarchy.

Multi-level inheritance simplifies building complex hierarchies, allowing each class to focus on its specific attributes and behaviors.

# Parent Class
class SatelliteImage:
    def __init__(self, sensor_type, spatial_resolution):
        self.sensor_type = sensor_type
        self.spatial_resolution = spatial_resolution

    def description(self):
        return f"Sensor Type: {self.sensor_type},\
        Resolution: {self.spatial_resolution} meters"

# Child Class
class OpticalImage(SatelliteImage):
    def __init__(self, sensor_type, spatial_resolution, cloud_coverage):
        super().__init__(sensor_type, spatial_resolution)
        self.cloud_coverage = cloud_coverage

    def description(self):
        parent_desc = super().description()
        return f"{parent_desc}, Cloud Coverage: {self.cloud_coverage}%"

# Grandchild Class
class MultiSpectralImage(OpticalImage):
    def __init__(self, sensor_type, spatial_resolution, cloud_coverage, bands):
        super().__init__(sensor_type, spatial_resolution, cloud_coverage)
        self.bands = bands

    def description(self):
        parent_desc = super().description()
        return f"{parent_desc}, Bands: {self.bands}"
image1 = SatelliteImage("Radar", "1–180 nm")
print(image1.description())
Sensor Type: Radar,        Resolution: 1–180 nm meters
image1 = OpticalImage("Radar", "1–180 nm", 20)
print(image1.description())
Sensor Type: Radar, Resolution: 1–180 nm meters, Cloud Coverage: 20%
image1 = MultiSpectralImage("Radar", "1–180 nm", 20, 4)
print(image1.description())

If you are not careful, inheritance can lead you to a huge hierarchical structure of classes that is hard to understand and maintain. This is known as the **class explosion problem.

3 What is Composition?

Composition and inheritance are key concepts in object-oriented programming (OOP) that model relationships between classes. Both are used to design reusable, maintainable, and flexible code, but they differ in how they establish relationships:

  • Inheritance: Models an “is a” relationship.
  • Composition: Models a “has a” relationsh.n?

Composition enables creating complex types by combining objects of other types. A class (called a composite) contains objects of another class (called components). This relationship is expressed as “A has a B.”

3.1 Key Features of Composition

  1. Loosely Coupled: Changes in the component class rarely affect the composite class, making the design adaptable to changes.
  2. Flexible Design: You can change behavior by providing new components rather than creating new subclasses.
  3. Code Reuse: Composite classes leverage the functionality of components withouing.iteImage`

3.2 Inheritance vs. Composition

  • Inheritance: Use for “is a” Relationships. (A subclass inherits the interface and implementation of its parent class.)

Example: A RadarImage “is a” SatelliteImage.

  • Composition: Use for “has a” Relationships. (A composite class contains a component class as an attribute.)

Example: A SatelliteImage “has a” Metadata.

Choosing Between Inheritance and Composition

Use Inheritance:

When you can confidently model an “is a” relationship. Example: A RadarImage class that extends SatelliteImage because it is a specialized type of satellite image.

Use Composition:

When you need to add behavior or functionality without altering the inheritance hierarchy. Example: Adding metadata or other components to SatelliteImage without modifying the base class.

Advantages of Composition Flexibility: Component behavior can be changed without affecting the composite. Reusability: Component classes can be reused across multiple composite classes. Simpler Code: Avoids the complexity of deep inheritance hierarchies (the class explosion problem).

Example: Extending Behavior with Composition Let’s add a “processing pipeline” component to the SatelliteImage class.

# Define the Component Class
class ProcessingPipeline:
    def __init__(self, steps):
        self.steps = steps

    def __str__(self):
        return " -> ".join(self.steps)

# Modify the Composite Class
class SatelliteImage:
    def __init__(self, sensor_type, spectral_resolution,
                 spatial_resolution, temporal_resolution,
                 metadata, pipeline):
        self.sensor_type = sensor_type
        self.spectral_resolution = spectral_resolution
        self.spatial_resolution = spatial_resolution
        self.temporal_resolution = temporal_resolution
        self.metadata = metadata  # Composition: Adding metadata
        self.pipeline = pipeline  # Composition: Adding a processing pipeline

    def description(self):
        return (
            f"Sensor Type: {self.sensor_type}, "
            f"Spectral Resolution: {self.spectral_resolution}, "
            f"Spatial Resolution: {self.spatial_resolution} meters, "
            f"Temporal Resolution: {self.temporal_resolution} days, "
            f"{self.metadata}, "
            f"Pipeline: {self.pipeline}"
        )
# Create Metadata and Pipeline objects
metadata = Metadata("NASA", "2025-01-22")
pipeline = ProcessingPipeline(["Load", "Preprocess",
                               "Analyze", "Visualize"])

image = SatelliteImage("Optical", 13, 10, 5, metadata,
                       pipeline)

print(image.description())
Sensor Type: Optical, Spectral Resolution: 13, Spatial Resolution: 10 meters, Temporal Resolution: 5 days, Source: NASA, Timestamp: 2025-01-22, Pipeline: Load -> Preprocess -> Analyze -> Visualize

Formulas for Vegetation Indices

Use the following formulas for calculating vegetation indices (VIs):

1. Normalized Difference Vegetation Index (NDVI) NDVI = (NIR - R) / (NIR + R)

2. Green Normalized Difference Vegetation Index (GNDVI) GNDVI = (NIR - G) / (NIR + G)

3. Enhanced Vegetation Index (EVI) EVI = 2.5 * ((NIR - R) / (NIR + 6R - 7.5B + 1))

Where: - NIR: Near-Infrared band - R: Red band - G: Green band - B: Blue band
